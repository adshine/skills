## Principles

- **Use roles, not hex values.** Components ask for `var(--primary)` or `var(--muted)`, never a hex value. That is what makes dark mode and future brand changes a one-file edit.
- **Every fill has a paired text color.** `primary` goes with `primary-foreground`, `destructive` with `destructive-foreground`. Use the pair together.
- **Generated, not hand-picked.** The palette comes from one seed color through a contrast-aware color model, so every pair is readable.

## Using color in code

Read roles with `var()` in any CSS, including a WordPress theme's custom CSS or a Webflow embed:

```css
.booking-panel {
  background: var(--card);
  color: var(--card-foreground);
  border: 1px solid var(--border);
}
```

For a tint, mix a role with transparent instead of inventing a new color:

```css
.highlight {
  background: color-mix(in oklab, var(--primary) 10%, transparent);
}
```

## Changing the palette

Do not edit `theme.css` by hand. Rerun the generator with a new seed and replace the file:

```bash
scripts/seed-to-tokens.sh --seed "#1D4ED8" --variant fidelity --shadcn theme.css
```

Every component and every page of these docs picks up the new colors with no other change.

## Accessibility

Text pairs meet WCAG 2.2 AA (4.5:1), and borders, focus rings and form fields meet 3:1 in both themes. Never use color alone to carry meaning: pair it with text or an icon, like an error message under a red field.
