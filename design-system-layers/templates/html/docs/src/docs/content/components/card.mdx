## Anatomy

1. **Container:** `card`, with the card background, border and padding.
2. **Title:** `card__title`. A heading, so it shows up in the page outline.
3. **Description:** `card__desc`, quiet supporting text.
4. **Content:** anything in between, such as a price, a list or an avatar row.
5. **Footer:** `card__footer`, the actions, at most one primary.

## When to use

- To show several items of the same kind side by side, like services, plans or team members.
- To group a summary and its actions, so it is clear which button belongs to which item.

## When not to use

- **For a single block of page content.** A heading and a section are enough; a border adds noise.
- **For dense data with many rows.** Use a table so people can scan and compare.
- **Nested inside another card.** Use spacing or a divider instead.

## Content

- Lead with the title people scan for: the service name, the plan name, the person.
- Keep descriptions to one or two lines. Long text belongs on a detail page.
- Cards in a set have the same structure in the same order, so people can compare them.

## Markup

```html
<article class="card">
  <div>
    <h3 class="card__title">Website audit</h3>
    <p class="card__desc">Speed, search ranking and accessibility review.</p>
  </div>
  <div class="card__footer">
    <button class="btn">Book an audit</button>
  </div>
</article>
```

| Class | What it does |
| --- | --- |
| `card` | Background, border, rounded corners, padding and even spacing between children |
| `card__title` | Title text. Use a heading element at the right level for the page. |
| `card__desc` | Quiet supporting text |
| `card__footer` | Row of actions that wraps on small screens |

## Title as a heading

Use the heading level that fits the page: if the cards sit under an `h2` section title, use `h3` for card titles. The class sets the look; the element sets the outline that screen reader users navigate by.

## Whole card as a link

When the whole card goes to one place, make the title a link and do not wrap the card in an `a`. Wrapping makes screen readers read the entire card as one long link.

```html
<article class="card">
  <h3 class="card__title"><a href="/services/audit">Website audit</a></h3>
  <p class="card__desc">Speed, search ranking and accessibility review.</p>
</article>
```

## Grid of cards

```html
<div style="display:grid;gap:1.5rem;grid-template-columns:repeat(auto-fit,minmax(16rem,1fr))">
  <article class="card">...</article>
  <article class="card">...</article>
  <article class="card">...</article>
</div>
```

## WordPress and Webflow

- **WordPress:** add `card` to a Group block under **Advanced, Additional CSS class(es)**, then put a Heading with `card__title` and a Paragraph with `card__desc` inside it.
- **Webflow:** give a Div Block the class `card`, and its heading and paragraph the classes `card__title` and `card__desc`. Collection lists of cards work the same way.

## Styling

Cards read `--card`, `--card-foreground`, `--border` and `--radius`. Spacing between children comes from the card's grid gap, so do not add margins to children.

## Keyboard

Cards are not focusable themselves. Focus moves through the links and buttons inside them in reading order.

| Key | Action |
| --- | --- |
| <kbd>Tab</kbd> | Moves to the next link or button in the card |
| <kbd>Enter</kbd> | Follows the focused link or activates the focused button |

## Checklist

- Titles are real headings at the right level, so the page outline makes sense.
- Use `article` for cards that stand on their own, like a service or a post.
- Button labels make sense out of context: "Book an audit", not "Book" repeated in every card.
- Do not wrap a whole card in a link; link the title.
- Loading cards set `aria-busy="true"` and have a label.
- Card borders use `--border`; the content inside still meets text contrast in light and dark.
