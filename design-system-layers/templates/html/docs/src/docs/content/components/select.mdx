## When to use

- To choose one option from about six to fifteen known choices, like a service, a time slot or a department.
- When space is tight and the choices do not need comparing side by side.

## When not to use

- **For two to five options.** Use [radio buttons](/components/radio) so every choice is visible without opening anything.
- **For long lists people search through,** like countries. A text field with suggestions works better than scrolling.
- **For actions.** A select changes a value. To run a command, use a [button](/components/button).
- **For several choices at once.** Use [checkboxes](/components/checkbox). Multi-select lists are hard to use on every device.

/>

Use `optgroup` when the list has natural groups. Show unavailable options as disabled with the reason in the label, rather than hiding them, so people know they exist.

## Content

- Order options in a way people expect: by time, by size, or alphabetically. Put the most common choice first only if the list is short.
- Keep option labels short and parallel: "Small", "Medium", "Large", not "Small size", "Medium", "Big one".
- The prompt option says what to do: "Choose a service".

## Markup

```html
<div class="field">
  <label class="label" for="service">Service</label>
  <select class="select" id="service" name="service" required>
    <option value="">Choose a service</option>
    <option value="audit">Website audit</option>
    <option value="brand">Brand refresh</option>
  </select>
</div>
```

| Class | What it does |
| --- | --- |
| `select` | Styles a native `select` to match text fields. Fills its container. |
| `field`, `label`, `field-hint`, `field-error` | Same as [text field](/components/text-field) |

The native element keeps the platform picker: a wheel on iPhone, a sheet on Android, a list on desktop. That is better on phones than any custom dropdown, so do not replace it with a `div` menu.

## Error state

Add `aria-invalid="true"` and link the message with `aria-describedby`, exactly as for a text field. With `required` and an empty prompt option, `components.js` catches an empty choice on submit when the form has `data-validate`.

## WordPress and Webflow

- **WordPress:** give the form plugin's dropdown field the class `select`, or paste the markup into a Custom HTML block.
- **Webflow:** give a Select element the class `select` and leave its Webflow styles empty.

## Styling

The select reads the same roles as a text field: `--input`, `--ring`, `--destructive` and `--radius`. The arrow is the browser's own, so it follows the text color in light and dark mode.

## Keyboard

| Key | Action |
| --- | --- |
| <kbd>Tab</kbd> | Moves focus to the select |
| <kbd>Space</kbd> or <kbd>Enter</kbd> | Opens the list (on most browsers) |
| <kbd>Up</kbd> or <kbd>Down</kbd> | Moves through options |
| Typing a letter | Jumps to the next option starting with that letter |
| <kbd>Escape</kbd> | Closes the list without changing the value |

## Checklist

- Every select has a visible `label` tied to it with `for` and `id`.
- The native element is used, so screen readers announce it as a list with the current value and option count.
- Errors set `aria-invalid="true"` and the message is linked with `aria-describedby`.
- Disabled options say why in their label, like "(full)".
- Do not submit or navigate as soon as the value changes; people using a keyboard move through options one by one.
