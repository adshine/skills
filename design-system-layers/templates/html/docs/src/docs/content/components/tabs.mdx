## When to use

- To switch between views of the same content: monthly or yearly prices, a product's details and its reviews.
- When people only need one view at a time and the views are about the same size.
- For two to five options with short labels.

## When not to use

- **For navigation between pages.** Use links in the site navigation. Tabs do not change the address, so people cannot bookmark or share a tab.
- **For steps in a process.** Steps happen in order; tabs can be opened in any order. Use a form with numbered steps.
- **When people need to compare views.** Show them side by side instead.
- **For content people must read.** Hidden panels get missed. If everything matters, show everything.

## Content

- One or two words per label, in sentence case.
- Keep the first tab the one most people need.
- Do not put tabs inside tabs.

## Markup

```html
<div class="tabs">
  <div class="tabs__list" role="tablist" aria-label="Pricing period">
    <button class="tabs__tab" role="tab" id="tab-month"
            aria-selected="true" aria-controls="panel-month">Monthly</button>
    <button class="tabs__tab" role="tab" id="tab-year"
            aria-selected="false" aria-controls="panel-year" tabindex="-1">Yearly</button>
  </div>
  <div class="tabs__panel" role="tabpanel" id="panel-month" aria-labelledby="tab-month">...</div>
  <div class="tabs__panel" role="tabpanel" id="panel-year" aria-labelledby="tab-year" hidden>...</div>
</div>
```

| Class or attribute | What it does |
| --- | --- |
| `tabs` | Wrapper around the list and panels |
| `tabs__list` with `role="tablist"` | The rail of tabs. Give it an `aria-label`. |
| `tabs__tab` with `role="tab"` | One tab. `aria-controls` points at its panel. |
| `aria-selected="true"` | Marks the current tab and styles it as selected |
| `tabs__panel` with `role="tabpanel"` | The content. `aria-labelledby` points at its tab; add `hidden` to every panel but the first. |

Set `tabindex="-1"` on every tab except the selected one, so <kbd>Tab</kbd> moves into the tab list once and then on to the panel.

## Behavior

`components.js` finds every `role="tablist"` on the page and handles clicks, arrow keys, Home and End. It updates `aria-selected`, `tabindex` and `hidden` for you. Without the script, only the first panel shows, so the most important content belongs there.

If you add tabs after the page loads, call `DS.enhance(container)`.

## WordPress and Webflow

- **WordPress:** paste the markup into a Custom HTML block. Every `id` must be unique on the page, so rename them if you use tabs twice.
- **Webflow:** Webflow's own Tabs element works too, but it is styled separately. To use these styles, paste the markup into an Embed element.

## Styling

The rail uses `--muted`, the selected tab uses `--background` and `--foreground`, and other tabs use `--muted-foreground`. Corners follow `--radius`.

## Keyboard

| Key | Action |
| --- | --- |
| <kbd>Tab</kbd> | Moves focus to the selected tab, then into the panel |
| <kbd>Right arrow</kbd> or <kbd>Left arrow</kbd> | Selects the next or previous tab, wrapping around |
| <kbd>Home</kbd> or <kbd>End</kbd> | Selects the first or last tab |

## Focus management

Arrow keys move focus and show the new panel at the same time. Focus never jumps into the panel on its own; people press <kbd>Tab</kbd> to go there.

## Checklist

- The tab list has `role="tablist"` and an `aria-label` that names the set.
- Each tab has `role="tab"`, `aria-selected` and `aria-controls`; each panel has `role="tabpanel"` and `aria-labelledby`.
- Only the selected tab is in the tab order.
- Every `id` is unique on the page.
- The selected tab is shown by more than color: it has a raised background and a shadow.
- Labels fit on one line at 390 px wide.
