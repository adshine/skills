## The problem

A screen with no data, a long wait or a failure is where people most often get lost. A blank area looks broken, a spinner with no end looks stuck, and "Something went wrong" leaves people with nowhere to go. Each of these states needs to say what is happening and offer a next step.

## When to use

- **Empty**: a list, table or page that has no content yet, or no results for a search or filter.
- **Loading**: content takes longer than about 300ms to appear.
- **Error**: content fails to load or an action fails to complete.

Every screen that shows data needs all three. Design them alongside the happy path, not after.

## Empty states

There are three kinds, and each needs different words.

| Kind | Cause | What to show |
| --- | --- | --- |
| First use | Nothing has been created yet | What will appear here and the action to create the first one |
| No results | A search or filter matched nothing | What was searched, and a way to change or clear it |
| All done | People cleared their work, like an empty inbox | A short, calm confirmation. No action needed. |

## Loading states

Match the wait to the indicator.

| Wait | Show |
| --- | --- |
| Under 300ms | Nothing. A flash of loading UI feels slower than none. |
| 300ms to about 10 seconds, content area | Skeletons shaped like the content that is coming |
| 300ms to about 10 seconds, an action | Spinner inside the button, with the button disabled and a progress label |
| Over 10 seconds | A progress bar or steps, with time left if known, and a way to leave and come back |

<Example
  title="Skeleton shaped like a booking list"
  align="stretch"
  code={`<div className="mx-auto w-full max-w-sm space-y-4" aria-busy="true" aria-label="Loading bookings">
  {[0, 1, 2].map((i) => (
    <div key={i} className="flex items-center gap-3">
      <Skeleton className="size-10 rounded-full" />
      <div className="flex-1 space-y-2">
        <Skeleton className="h-4 w-3/5" />
        <Skeleton className="h-3 w-2/5" />
      </div>
    </div>
  ))}
</div>`}
>
  <div className="mx-auto w-full max-w-sm space-y-4" aria-busy="true" aria-label="Loading bookings">
    {[0, 1, 2].map((i) => (
      <div key={i} className="flex items-center gap-3">
        <Skeleton className="size-10 rounded-full" />
        <div className="flex-1 space-y-2">
          <Skeleton className="h-4 w-3/5" />
          <Skeleton className="h-3 w-2/5" />
        </div>
      </div>
    ))}
  </div>
</Example>

- Skeletons match the layout that replaces them, so nothing jumps when content arrives.
- Keep what is already known on screen. Load the page frame, headings and navigation first; only the data area shows skeletons.
- Show at most one loading indicator per area. Do not put a spinner on top of skeletons.
- Mark the loading region with `aria-busy="true"` and announce completion if focus does not move.

## Error states

An error message says what happened, whether anything was lost, and what to do now. Pick the scope that matches the failure.

| Scope | Use when | Component |
| --- | --- | --- |
| Field | One answer is wrong | Inline message under the field. See [Forms and validation](/patterns/forms-and-validation). |
| Section | One part of a page failed to load | Message in place of that section, with retry |
| Page | The whole page cannot load | Full-page message with retry and a way back |
| Action | Saving, paying or sending failed | Destructive alert near the action, or a toast if the page moved on |

## Recovery

- **Keep what people entered.** A failed save never clears a form or loses a draft.
- **Retry in place.** "Try again" reloads only what failed, not the whole page.
- **Retry automatically when safe.** Reading data can retry quietly once or twice; payments and other actions that cost money never retry without asking.
- **Say if it is our fault.** "We're having trouble on our side" is honest and stops people from changing things that were fine.
- **Offer a way out.** If retry keeps failing, link to help or a status page, and give a reference people can quote to support.
- **Confirm recovery.** When things work again, replace the error with the content. A short "Back online" toast is enough.

## Accessibility

- Error alerts use `role="alert"` (built into `Alert`), so they are announced as soon as they appear. Use it only for new errors, not on page load for old ones.
- Loading regions use `aria-busy="true"`; when loading finishes, focus stays where it was.
- Spinners and skeleton pulses use `motion-reduce:animate-none` where motion is not essential.
- Empty and error states use a real heading, so screen reader users can find them.
- Icons in these states are decorative; the text carries the message.
