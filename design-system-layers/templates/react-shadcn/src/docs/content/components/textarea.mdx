## When to use

- For answers that may run over one line: feedback, notes, descriptions, support messages.
- When people need to see and edit what they wrote as a whole before sending it.

## When not to use

- **For short, single values.** Use a [text field](/components/input) for names, emails and titles.
- **For formatted content.** A textarea is plain text only. Use a rich text editor if people need headings, links or lists.

## Content

- Labels name the content, in sentence case: "Message", "Delivery instructions".
- Use helper text to say what a good answer includes, for example "Include the page and what you expected to happen".
- Placeholders can suggest a starting point but must not hold required instructions.

## Live character count

```tsx
const [value, setValue] = React.useState("")
const left = 160 - value.length

<Label htmlFor="bio">Short bio</Label>
<Textarea
  id="bio"
  value={value}
  maxLength={160}
  onChange={(e) => setValue(e.target.value)}
  aria-describedby="bio-count"
/>
<p id="bio-count" aria-live="polite" className="text-sm text-muted-foreground">
  {left} characters left
</p>
```

## Capping the height

```tsx
<Textarea className="max-h-64 overflow-y-auto" />
```

## Keyboard

| Key | Action |
| --- | --- |
| <kbd>Tab</kbd> | Moves focus into the textarea |
| <kbd>Enter</kbd> | Adds a new line (it does not submit the form) |
| <kbd>Shift</kbd> + <kbd>Tab</kbd> | Moves focus to the previous field |

## Checklist

- Every textarea has a visible `Label` linked with `htmlFor` and `id`.
- Helper text, counts and errors are linked with `aria-describedby`.
- Live counts use `aria-live="polite"` so they are announced without interrupting typing.
- Errors set `aria-invalid="true"` and explain the fix in words.
- If you add a keyboard shortcut to submit, like <kbd>Ctrl</kbd> + <kbd>Enter</kbd>, say so in the helper text.
- The focus ring uses `--ring` and meets 3:1 contrast against the page.
