## When to use

- To confirm an action that is hard to undo, like deleting or removing access.
- To collect a small amount of input (one to three fields) without leaving the page.
- When people must deal with the question before they can carry on.

## When not to use

- **For long forms or multi-step flows.** Use a full page so people can scroll, save and come back.
- **For information people did not ask for.** Use an inline [alert](/components/alert) or a [toast](/components/toast).
- **For quick, reversible actions.** Do the action and offer undo in a toast instead of asking first.
- **For extra detail next to a control.** Use a [popover](/components/popover); it does not block the page.

## Confirm dialogs

A confirm dialog asks one question. The title is the question, the description says what happens, and the buttons repeat the verb. The safe choice sits on the left and closes the dialog.

## Destructive confirm

When the action deletes something or cannot be undone, use the destructive button and say exactly what will be lost.

## Content

- **Title:** a short question or task in sentence case, like "Delete this file?" or "Invite a teammate".
- **Description:** one or two sentences on what happens next. Say if it cannot be undone.
- **Buttons:** verb first, matching the title. Avoid "OK", "Yes" and "Confirm".
- Do not stack dialogs on top of each other. Finish or close one before opening another.

`DialogTrigger` and `DialogClose` accept `asChild` to render your own `Button`. `DialogHeader`, `DialogTitle` and `DialogDescription` pass other props to their elements.

## Controlled dialog

Control the open state when the dialog should close only after async work finishes:

```tsx
const [open, setOpen] = React.useState(false)

async function onSubmit(event: React.FormEvent) {
  event.preventDefault()
  await saveName()
  setOpen(false)
}

<Dialog open={open} onOpenChange={setOpen}>
  <DialogTrigger asChild>
    <Button>Rename project</Button>
  </DialogTrigger>
  <DialogContent>
    <form onSubmit={onSubmit}>...</form>
  </DialogContent>
</Dialog>
```

## Opening from a menu item

Open a dialog from a [menu](/components/dropdown-menu) by controlling it, so the menu can close first:

```tsx
const [open, setOpen] = React.useState(false)

<DropdownMenuItem onSelect={() => setOpen(true)}>Delete</DropdownMenuItem>
<Dialog open={open} onOpenChange={setOpen}>
  <DialogContent>...</DialogContent>
</Dialog>
```

## Styling

The panel uses `bg-background`, `border` and the `--radius` scale. The backdrop is a translucent black overlay. Change width with `className` on `DialogContent`; do not pass raw colors.

## Keyboard

| Key | Action |
| --- | --- |
| <kbd>Enter</kbd> or <kbd>Space</kbd> | On the trigger, opens the dialog |
| <kbd>Tab</kbd> | Moves to the next focusable element inside the dialog, looping at the end |
| <kbd>Shift</kbd> + <kbd>Tab</kbd> | Moves to the previous focusable element, looping at the start |
| <kbd>Esc</kbd> | Closes the dialog and returns focus to the trigger |

## Focus management

- On open, focus moves to the first focusable element in the dialog. For a destructive confirm, move it to the safe button with `autoFocus` on Cancel.
- Focus stays inside the dialog while it is open; the page behind is hidden from assistive technology.
- On close, focus returns to the element that opened the dialog. If that element no longer exists (for example after a delete), move focus somewhere sensible with `onCloseAutoFocus`.

## Checklist

- Every dialog has a `DialogTitle`. It is announced as the dialog name. If it must be hidden, keep it and add `className="sr-only"`.
- `DialogDescription` is announced with the title. If you leave it out, pass `aria-describedby={undefined}` to `DialogContent`.
- The close icon has the text "Close" for screen readers.
- Buttons use clear verbs, so they make sense when read on their own.
- The dialog fits small screens; long content scrolls inside the page, not off screen.
