## When to use

- To collect a single line of free text: a name, an email address, a phone number, a search term.
- When the answer is short and you cannot predict it well enough to offer a list.

## When not to use

- **For long answers.** Use a [textarea](/components/textarea) for comments, notes and descriptions.
- **When there are a few known answers.** Use a [select](/components/select) or a [radio group](/components/radio-group) so people choose instead of type.
- **For yes or no questions.** Use a [checkbox](/components/checkbox) or a [switch](/components/switch).

## Content

- **Labels** are short nouns in sentence case: "Email address", not "Please enter your email address".
- **Placeholders** show an example of the format, not instructions. Anything people must know goes in helper text.
- **Helper text** sits under the field and explains format or why you need the information.
- **Error messages** say what to do next: "Enter a date after today", not "Invalid input".
- Use the right `type` (`email`, `tel`, `url`, `search`, `number`) so phones show the right keyboard.

## Props

  { name: "type", type: "string", default: '"text"', description: "Native input type. Pick the most specific one, like email or tel." },

`Input` renders a native `input` element, and all other props pass through to it. `Label` wraps the Radix label primitive and accepts `htmlFor`.

## Field with helper and error text

Connect the label with `htmlFor` and `id`, and the message with `aria-describedby`. Swap helper text for the error when the value is wrong:

```tsx
<div className="grid gap-2">
  <Label htmlFor="email">Email address</Label>
  <Input
    id="email"
    type="email"
    aria-invalid={!!error}
    aria-describedby="email-message"
  />
  <p id="email-message" className={error ? "text-sm text-destructive" : "text-sm text-muted-foreground"}>
    {error ?? "We send receipts to this address."}
  </p>
</div>
```

## With an icon

Position the icon absolutely inside a relative wrapper and pad the input so text never sits under it:

```tsx
<div className="relative">
  <SearchIcon className="pointer-events-none absolute top-1/2 left-3 size-4 -translate-y-1/2 text-muted-foreground" />
  <Input type="search" aria-label="Search projects" className="pl-9" />
</div>
```

## Styling

Text fields read `--input` for the border, `--ring` for focus and `--destructive` for errors. Keep width set by the layout (the field fills its container) and do not override colors through `className`.

## Keyboard

| Key | Action |
| --- | --- |
| <kbd>Tab</kbd> | Moves focus into the field |
| <kbd>Shift</kbd> + <kbd>Tab</kbd> | Moves focus to the previous field |
| <kbd>Enter</kbd> | Submits the form the field belongs to |

## Checklist

- Every field has a visible `Label` tied to it with `htmlFor` and `id`. Fields without a visible label, like search, have an `aria-label`.
- Helper and error text are linked with `aria-describedby`, so they are read along with the label.
- Errors set `aria-invalid="true"` and are described in words, never by color alone.
- The focus ring uses `--ring` and meets 3:1 contrast against the page.
- Placeholder text is not the only label and is not used for required information.
- Use `autoComplete` values like `email` and `name` so browsers and password managers can fill the field.
