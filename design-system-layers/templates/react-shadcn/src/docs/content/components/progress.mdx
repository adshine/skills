import * as React from "react"
import { Button } from "@/components/ui/button"
import { Progress } from "@/components/ui/progress"

export function DemoUpload() {
  const [value, setValue] = React.useState(0)
  const [running, setRunning] = React.useState(false)
  React.useEffect(() => {
    if (!running) return
    const id = setInterval(() => setValue((v) => Math.min(100, v + 10)), 300)
    return () => clearInterval(id)
  }, [running])
  React.useEffect(() => {
    if (value >= 100) setRunning(false)
  }, [value])
  const done = value >= 100
  return (
    <div className="grid w-full max-w-sm gap-3">
      <div className="flex items-center justify-between text-sm">
        <span id="upload-label" className="font-medium">{done ? "Upload complete" : "Uploading report.pdf"}</span>
        <span className="text-muted-foreground tabular-nums">{value}%</span>
      </div>
      <Progress value={value} aria-labelledby="upload-label" />
      <div>
        <Button
          size="sm"
          variant="outline"
          disabled={running}
          onClick={() => {
            setValue(0)
            setRunning(true)
          }}
        >
          {done ? "Upload again" : "Start upload"}
        </Button>
      </div>
    </div>
  )
}

## When to use

- For tasks that take more than a couple of seconds and where you know how much is done, like uploads, imports and exports.
- To show completion of a known set of steps, like a profile that is 60 percent complete.
- To show usage against a limit, like storage used.

## When not to use

- **When you cannot measure progress.** Use a spinner in the button, or a [skeleton](/components/skeleton) for loading content.
- **For waits under about a second.** A bar that flashes and disappears is distracting.
- **For steps people move through themselves.** Use a stepper that names each step.

Set `value` from 0 to 100. The bar fills from the left with the `--primary` role on a light primary track.

## Content

- Label the task with a verb in the present tense: "Uploading 3 files", "Exporting report".
- Show the percentage or a count ("2 of 5 files") next to the bar.
- When finished, change the label to the result ("Upload complete") or remove the bar.
- If the task fails, keep the bar where it stopped and show an error with a retry action.

## Props

<PropsTable props={[
  { name: "value", type: "number | null", description: "How much is done, from 0 to 100. The indicator width is based on this value." },
  { name: "max", type: "number", default: "100", description: "Upper bound read by assistive technology. Keep it at 100; the bar width assumes a 0 to 100 scale." },
  { name: "getValueLabel", type: "(value: number, max: number) => string", description: "Text read by screen readers. Defaults to a percentage." },
  { name: "className", type: "string", description: "Extra classes on the track, for example h-1 or h-3 to change the height." },
]} />

All other props pass to the Radix Progress root. There is no indeterminate animation in this component; a `null` value shows an empty track.

## Counting steps

Convert a count into a percentage before passing it in:

```tsx
const value = Math.round((filesDone / filesTotal) * 100)

<Progress
  value={value}
  aria-label="Uploading files"
  getValueLabel={() => filesDone + " of " + filesTotal + " files uploaded"}
/>
```

## Styling

The track reads `--primary` at 20 percent opacity and the indicator reads `--primary`. Change height with a class on the root; keep the rounded ends.

## Keyboard

Progress bars are not interactive and do not take focus.

| Key | Action |
| --- | --- |
| None | Progress is read by screen readers but has no keyboard behavior |

## Focus management

- Focus stays where it is while a task runs. Do not move focus to the bar.
- When the task finishes, announce the result with a [toast](/components/toast) or a status message, and move focus only if the next step needs it.

## Checklist

- The bar has `role="progressbar"` with `aria-valuenow`, `aria-valuemin` and `aria-valuemax` set from Radix.
- Every bar has an accessible name with `aria-label` or `aria-labelledby` pointing at its visible label.
- The percentage is also shown as text, not only by bar length.
- The indicator against the track meets 3:1 contrast in light and dark.
- Long tasks do not rely on the bar alone; people can leave the page and come back or get notified when done.
