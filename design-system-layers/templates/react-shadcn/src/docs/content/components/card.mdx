1. **Header** holds the title, description and action in a grid.
2. **Title** names the subject in a few words.
3. **Description** adds one line of context, like status or date.
4. **Action** (optional) sits top right for a menu, badge or quick action.
5. **Content** is the body: text, data, a form or a list.
6. **Footer** (optional) holds the main actions for the card.

## When to use

- To show a set of similar items people browse and compare, like projects, plans or articles.
- To group one subject's details and actions on a dashboard or settings page.

## When not to use

- **For a single block of page content.** A heading and a section are enough; a border adds noise.
- **For dense data with many rows.** Use a table so people can scan and sort.
- **Nested inside another card.** Use spacing or a separator instead.

## Content

- Titles are short and specific, in sentence case: "Team plan", not "Your Current Subscription Plan Details".
- Keep cards in a set the same structure, so people compare like with like.
- Put at most one primary [button](/components/button) on a card. In a grid of cards, consider making the whole card a link instead.

## Title as a heading

`CardTitle` is a `div`. When the card title belongs in the page outline, render a real heading inside it:

```tsx
<CardHeader>
  <CardTitle>
    <h3>Team plan</h3>
  </CardTitle>
</CardHeader>
```

## Whole card as a link

```tsx
<Card className="relative transition-colors hover:bg-accent/40">
  <CardHeader>
    <CardTitle>
      <a href="/projects/atlas" className="after:absolute after:inset-0">
        Project Atlas
      </a>
    </CardTitle>
    <CardDescription>Updated 2 hours ago</CardDescription>
  </CardHeader>
</Card>
```

The stretched link keeps one clear link name for screen readers while the whole card is clickable.

## Grid of cards

```tsx
<div className="grid gap-4 sm:grid-cols-2 lg:grid-cols-3">
  {projects.map((p) => (
    <Card key={p.id}>...</Card>
  ))}
</div>
```

## Styling

Cards read `--card`, `--card-foreground` and `--border`. Change radius and shadow in the theme, not per card.

## Keyboard

A card is not interactive itself. Focus moves through the links and buttons inside it in reading order.

| Key | Action |
| --- | --- |
| <kbd>Tab</kbd> | Moves to the next link or button inside the card |
| <kbd>Enter</kbd> | Follows the card link, when the whole card is a link |

## Checklist

- Card titles that structure the page use a real heading level that fits the outline.
- When the whole card is clickable, there is one link with a clear name, not a link wrapping all the content.
- Buttons inside a clickable card stay reachable and sit above the stretched link (`relative z-10`).
- Icon-only actions in `CardAction` have an `aria-label`.
- Text on `--card` meets 4.5:1 contrast in light and dark. See [Color](/foundations/color).
- Groups of cards in a list use a `ul` or `role="list"` so screen readers announce the count.
