## When to use

- For settings that apply the moment they change, with no save button: notifications, dark mode, auto-renew.
- When the setting has two clear states, on and off.

## When not to use

- **Inside a form that is submitted later.** Use a [checkbox](/components/checkbox).
- **For choices that are not on or off,** like "Monthly or yearly". Use a [radio group](/components/radio-group).
- **For actions.** "Turn on now" that runs a process is a [button](/components/button).

## Switch or checkbox

| | Switch | Checkbox |
| --- | --- | --- |
| Takes effect | Immediately | When the form is submitted |
| Typical place | Settings pages and lists | Forms, filters and tables |
| Several options | Each is independent | Can be grouped under one question |
| Label reads as | A setting: "Email alerts" | A statement: "I agree to the terms" |

## Content

- Label the setting, not the action: "Email alerts", not "Turn on email alerts".
- Do not change the label when the state changes; the switch already shows on or off.
- If switching takes time or can fail, show progress and roll back with a message when it fails.

## Saving right away

Update the UI first, then save, and roll back if the save fails:

```tsx
const [on, setOn] = React.useState(settings.emailAlerts)

async function handleChange(next: boolean) {
  setOn(next)
  try {
    await saveSetting("emailAlerts", next)
  } catch {
    setOn(!next)
    toast.error("Could not update email alerts. Try again.")
  }
}

<div className="flex items-center justify-between gap-4">
  <Label htmlFor="email-alerts">Email alerts</Label>
  <Switch id="email-alerts" checked={on} onCheckedChange={handleChange} />
</div>
```

## Keyboard

| Key | Action |
| --- | --- |
| <kbd>Tab</kbd> | Moves focus to the switch |
| <kbd>Space</kbd> or <kbd>Enter</kbd> | Turns it on or off |

## Checklist

- Every switch has a name, from a `Label` linked with `htmlFor` and `id`, or an `aria-label`.
- It is announced as a switch with its state ("on" or "off"), because Radix sets `role="switch"` and `aria-checked`.
- The thumb position shows the state, not color alone.
- Descriptions are linked with `aria-describedby`.
- Errors when saving are announced, for example with a toast or a live region, and the switch returns to its last saved state.
- The clickable area (switch plus label) is at least 44 by 44 px on touch screens.
