## When to use

- To group secondary actions for an item, like edit, duplicate and delete, behind one button.
- When space is tight, such as on table rows, cards and toolbars.
- To let people switch a view setting, like sort order or visible columns.

## When not to use

- **For the main action.** Put it on its own button so people can see it without opening anything.
- **To pick a value in a form.** Use a select or radio group so the chosen value stays visible.
- **For navigation between pages.** Use links or tabs.
- **For one or two actions.** Show them as buttons instead.

## Overflow menu

An icon-only trigger keeps rows and cards quiet. Give it an `aria-label` that names the item.

## Options, groups and submenus

Checkbox items turn a setting on or off. Radio items pick one option from a group. Labels and separators group related items. Use a submenu only when a group would make the main list too long.

## Content

- Start each item with a verb: "Rename", "Move to folder", "Copy link".
- Keep items to one to three words, in sentence case.
- Order by how often people use them, with destructive items last.
- Aim for seven items or fewer. Split longer lists with labels or move rare actions elsewhere.
- Show a disabled item only when people would expect it there; otherwise leave it out.
- Destructive items that cannot be undone should open a [dialog](/components/dialog) to confirm.

`DropdownMenuCheckboxItem` takes `checked`, `defaultChecked` and `onCheckedChange`. `DropdownMenuRadioGroup` takes `value`, `defaultValue` and `onValueChange`; each `DropdownMenuRadioItem` needs a `value`. `DropdownMenuLabel` and `DropdownMenuSubTrigger` accept `inset`. `DropdownMenuShortcut` is a plain `span` for a hint on the right.

## Controlled checkbox items

```tsx
const [showStatus, setShowStatus] = React.useState(true)

<DropdownMenuCheckboxItem checked={showStatus} onCheckedChange={setShowStatus}>
  Status
</DropdownMenuCheckboxItem>
```

## Opening a dialog from an item

Control the dialog and open it from `onSelect`. The menu closes first, then the dialog takes focus:

```tsx
const [confirmOpen, setConfirmOpen] = React.useState(false)

<DropdownMenuItem variant="destructive" onSelect={() => setConfirmOpen(true)}>
  Delete
</DropdownMenuItem>

<Dialog open={confirmOpen} onOpenChange={setConfirmOpen}>
  <DialogContent>...</DialogContent>
</Dialog>
```

## Styling

The menu reads `--popover` and `--popover-foreground`; the highlighted item reads `--accent` and `--accent-foreground`. Set width with `className` on `DropdownMenuContent`.

## Keyboard

| Key | Action |
| --- | --- |
| <kbd>Enter</kbd>, <kbd>Space</kbd> or <kbd>Arrow down</kbd> | On the trigger, opens the menu and focuses the first item |
| <kbd>Arrow down</kbd> / <kbd>Arrow up</kbd> | Moves to the next or previous item |
| <kbd>Home</kbd> / <kbd>End</kbd> | Moves to the first or last item |
| <kbd>Enter</kbd> or <kbd>Space</kbd> | Selects the focused item |
| <kbd>Arrow right</kbd> | Opens a submenu |
| <kbd>Arrow left</kbd> | Closes a submenu |
| Typing a letter | Moves to the next item that starts with that letter |
| <kbd>Esc</kbd> | Closes the menu and returns focus to the trigger |

## Focus management

- Opening the menu moves focus into it. Closing returns focus to the trigger.
- Focus moves item by item with the arrow keys; <kbd>Tab</kbd> closes the menu.
- Disabled items are skipped.

## Checklist

- The trigger is a real button with a visible label, or an `aria-label` if it is icon-only.
- The menu uses `role="menu"` and items use `role="menuitem"`, `menuitemcheckbox` or `menuitemradio`, so state is announced.
- Shortcut hints are decoration only. If a shortcut really exists, wire it up separately.
- Destructive items are not identified by color alone; the label says what happens.
- Items are at least 32 px tall, and the trigger meets the 44 by 44 px touch target.
