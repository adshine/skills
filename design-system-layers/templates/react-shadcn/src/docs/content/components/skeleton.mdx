## When to use

- While loading content whose shape you know, like cards, lists and tables.
- On first load of a page or section, so the layout is in place before the data.
- When loading usually takes between about half a second and a few seconds.

## When not to use

- **For actions people started, like saving.** Show progress in the button that was clicked.
- **For long tasks with measurable progress.** Use a [progress bar](/components/progress).
- **When the shape is unknown.** A skeleton that does not match the real layout causes a jump anyway. Use a simple spinner.
- **For empty states.** If there is no data, say so; do not leave a skeleton showing.

## Shapes

Build skeletons from a few blocks that match the real layout: a circle for avatars, bars for text lines, and a box for images.

## Guidance

- Match the size and position of the real content as closely as you can.
- Vary text bar widths a little, so they read as lines of text.
- Keep it simple: three to five blocks per item is plenty.
- Show skeletons only for the part that is loading. Keep headings, navigation and buttons real.
- Swap in real content all at once, not one block at a time.

## Props

<PropsTable props={[
  { name: "className", type: "string", description: "Sets size and shape, for example h-4 w-1/2 or size-10 rounded-full." },
]} />

`Skeleton` is a `div` with a pulse animation, rounded corners and the `--accent` background. All other props pass through.

## Loading pattern

Render the skeleton while data loads and swap it for the real component when it arrives. Mark the region busy so screen readers wait:

```tsx
<section aria-busy={isLoading} aria-live="polite">
  {isLoading ? (
    <>
      <span className="sr-only">Loading projects</span>
      <ProjectListSkeleton />
    </>
  ) : (
    <ProjectList projects={data} />
  )}
</section>
```

## Reusable skeletons

Keep a skeleton next to the component it stands in for, so they change together:

```tsx
export function ProjectCardSkeleton() {
  return (
    <div className="grid gap-3 rounded-xl border p-4">
      <Skeleton className="h-4 w-2/3" />
      <Skeleton className="h-3 w-1/3" />
    </div>
  )
}
```

## Styling

Skeletons read `--accent`, so they follow light and dark themes. Do not set custom colors; adjust only size, shape and spacing.

## Keyboard

Skeletons are decorative and never take focus.

| Key | Action |
| --- | --- |
| None | Skeletons are skipped by the keyboard |

## Focus management

- Do not put focusable elements inside a skeleton.
- When content loads, leave focus where it was. Do not jump to the new content.

## Checklist

- Skeleton blocks have no text, so screen readers ignore them. Add one visually hidden "Loading" message per region instead.
- The loading region has `aria-busy="true"` while loading, then `false` when content is in place.
- The pulse animation is gentle and does not flash.
- Skeleton blocks have enough contrast against the background to be seen, but less than real content.
