## When to use

- To show many records with the same fields, like orders, invoices or members.
- When people need to compare values across rows or sort and scan a column.
- To show exact numbers that would be hard to read in a chart.

## When not to use

- **For layout.** Use grid or flex for placing things on a page.
- **For a few items with rich content.** Use a list or cards.
- **On small screens with many columns.** Show the key columns and move the rest to a detail view, or switch to a list of cards.

## Status and row actions

Use a [badge](/components/badge) for status and an overflow [menu](/components/dropdown-menu) at the end of the row for actions. Name the row in the menu button label.

## Content

- Column headers are short nouns in sentence case: "Customer", "Due date".
- Align text left and numbers right. Match the header alignment to its column.
- Use the same format for every value in a column: dates, currency, units.
- Put the column people scan first on the left, usually the name or id.
- Show a dash for missing values rather than leaving the cell blank.

## Selected rows

Rows read `data-state` for selection styling. Pair a checkbox in the first cell with the row state:

```tsx
<TableRow data-state={selected ? "selected" : undefined}>
  <TableCell>
    <Checkbox checked={selected} onCheckedChange={toggle} aria-label="Select INV-1042" />
  </TableCell>
  ...
</TableRow>
```

## Sorting

Put a button inside the header cell and set `aria-sort` on the `th`:

```tsx
<TableHead aria-sort={sort === "asc" ? "ascending" : "descending"}>
  <Button variant="ghost" size="sm" onClick={toggleSort}>
    Amount
  </Button>
</TableHead>
```

## Styling

Borders use `--border`, row hover and the footer use `--muted`, and the caption uses `--muted-foreground`. Use `tabular-nums` and `text-right` on numeric columns.

## Keyboard

Tables are not interactive on their own. Only controls inside cells take focus.

| Key | Action |
| --- | --- |
| <kbd>Tab</kbd> | Moves to the next button, link or checkbox inside the table |
| <kbd>Shift</kbd> + <kbd>Tab</kbd> | Moves to the previous one |

## Focus management

- Do not make whole rows focusable or clickable without a real link or button inside. Put the main link on the name cell.
- When a row is deleted, move focus to the next row's action or to the table caption.

## Checklist

- Uses native `table`, `th` and `td`, so screen readers announce row and column headers.
- Every table has a `TableCaption` or an `aria-label` that says what it holds. Hide the caption with `sr-only` if needed.
- Icon-only buttons in rows name the row, like "Actions for INV-1042".
- Status is shown in words, not only by badge color.
- Wide tables scroll inside their container, so the page does not scroll sideways on small screens.
