## When to use

- To trigger an action on the current page: submit a form, confirm a choice, open a dialog.
- When the result happens right away or after a short wait, not when it takes people somewhere else.

## When not to use

- **To go to another page.** Use a link. Links say "this takes you somewhere"; buttons say "this does something".
- **For several equal options.** Use a radio group or tabs so people can see all choices at once.

## Choosing a variant

| Variant | Use for | Limit |
| --- | --- | --- |
| Primary | The one main action in a view | One per view or card |
| Secondary | Supporting actions next to a primary | Any |
| Outline | Neutral actions that should stay quiet | Any |
| Ghost | Actions in toolbars, menus and dense areas | Needs a clear label or icon tooltip |
| Destructive | Actions that delete or cancel something | Always confirm if it cannot be undone |
| Link | Low-emphasis actions inside text | Not for navigation |

## Labels

Start with a verb and say what will happen: "Book slot", "Pay deposit", "Cancel booking". Avoid "OK", "Submit" and "Click here". Keep labels to one to three words, in sentence case.

<DoDont>
  <Do caption="Specific verb, so people know what happens next.">
    <Button>Pay $50 deposit</Button>
  </Do>
  <Dont caption="Vague label that hides the consequence.">
    <Button>Submit</Button>
  </Dont>
</DoDont>

All other props pass through to the native `button` element.

## As a link

When something must look like a button but navigates, render a link inside with `asChild`:

```tsx
<Button asChild>
  <a href="/bookings">View bookings</a>
</Button>
```

## Loading state

Disable the button and keep the label meaningful while work is in progress, so people do not tap twice:

```tsx
<Button disabled={saving}>
  {saving && <Loader2Icon className="animate-spin" />}
  {saving ? "Saving" : "Save changes"}
</Button>
```

## Styling

Buttons read only theme roles: `--primary` and `--primary-foreground` for the primary variant, `--destructive` and `--destructive-foreground` for destructive. Never pass raw colors through `className`; add a variant instead.

## Keyboard

| Key | Action |
| --- | --- |
| <kbd>Tab</kbd> | Moves focus to the button |
| <kbd>Enter</kbd> or <kbd>Space</kbd> | Activates the button |

## Checklist

- Uses a native `button` element, so it is announced as a button and works with the keyboard by default.
- The focus ring uses `--ring` and meets 3:1 contrast against the page.
- Text on every variant meets 4.5:1 contrast in light and dark. See [Color](/foundations/color).
- Icon-only buttons have an `aria-label` that says what happens, like "Delete booking".
- Disabled buttons are skipped by assistive technology; if people need to know why something is unavailable, say so in nearby text.
- Minimum target size is 44 by 44 px on touch screens.
