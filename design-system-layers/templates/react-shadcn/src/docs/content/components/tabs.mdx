## When to use

- To split one topic into a few views at the same level, like Overview, Activity and Settings.
- When people only need one view at a time and do not need to compare them side by side.
- To switch a small area between two to five modes, like Monthly and Yearly pricing.

## When not to use

- **For steps in a process.** Use a stepper or separate pages, so order is clear.
- **When people need to compare content.** Show it side by side or in a [table](/components/table).
- **To move between unrelated pages.** Use the main navigation.
- **For one or two short sections.** Show them both, or use an [accordion](/components/accordion) on narrow screens.

## Content

- One or two words per label, in sentence case, using nouns: "Overview", "Files".
- Keep labels parallel in form and similar in length.
- Two to five tabs. More than that is hard to scan; consider a select or a sidebar.
- Open the most useful tab first, not always the first in the list.
- Do not hide required inputs in a tab people may never open.

## Syncing with the URL

Control the tabs so a link can open a specific view:

```tsx
const [params, setParams] = useSearchParams()
const tab = params.get("tab") ?? "overview"

<Tabs value={tab} onValueChange={(v) => setParams({ tab: v })}>
  ...
</Tabs>
```

## Styling

The track reads `--muted`; the active tab reads `--background` and `--foreground`, with `--input` borders in dark mode. The line variant uses `--foreground` for the underline.

## Keyboard

| Key | Action |
| --- | --- |
| <kbd>Tab</kbd> | Moves focus to the active tab, then into the open panel |
| <kbd>Arrow left</kbd> / <kbd>Arrow right</kbd> | Moves between tabs in a horizontal list |
| <kbd>Arrow up</kbd> / <kbd>Arrow down</kbd> | Moves between tabs in a vertical list |
| <kbd>Home</kbd> / <kbd>End</kbd> | Moves to the first or last tab |
| <kbd>Enter</kbd> or <kbd>Space</kbd> | Opens the focused tab when `activationMode` is manual |

## Focus management

- Only the active tab is in the <kbd>Tab</kbd> order. Arrow keys move between tabs.
- With automatic activation, moving focus also switches the panel.
- The open panel is focusable, so keyboard users can reach content even when it has no links or inputs.

## Checklist

- The list uses `role="tablist"`, each trigger `role="tab"` with `aria-selected`, and each panel `role="tabpanel"` linked to its tab.
- The active tab is shown by more than color: a raised surface in the default variant and an underline in the line variant.
- Focus rings use `--ring` and are visible on every tab.
- Labels make sense when read alone, without the panel.
