## When to use

- To confirm an action people just took, like "Message sent" or "File uploaded".
- To offer a quick undo after a reversible action.
- To report the result of background work that finishes while people do something else.

## When not to use

- **For form errors.** Show them inline next to the field, so people can see and fix them.
- **For anything people must read or act on.** Toasts vanish. Use an inline [alert](/components/alert) or a [dialog](/components/dialog).
- **For long messages.** If it needs more than a short sentence, it belongs on the page.
- **For every click.** If the change is already visible on screen, a toast only adds noise.

## Toast or inline message

| Situation | Use |
| --- | --- |
| An action worked and the result is not visible | Toast |
| A reversible action, like archive or remove from list | Toast with an Undo action |
| A field is wrong or missing | Inline error under the field |
| A problem blocks the whole page or form | Inline [alert](/components/alert) at the top |
| A status people need to keep seeing, like a trial ending | Inline alert or banner |
| An action that cannot be undone | Confirm in a [dialog](/components/dialog) first, then a toast |

## Content

- Say what happened in the past tense: "Invite sent", "File deleted".
- One short line. Add a description only if it helps, and keep it to one sentence.
- Errors say what to do next: "Upload failed. Try again."
- At most one action. Never put a destructive action in a toast.
- Do not say "Successfully". "Saved" is enough.

## Updating a toast

Reuse the id to turn a loading toast into a result:

```tsx
const id = toast.loading("Uploading file")
try {
  await upload(file)
  toast.success("File uploaded", { id })
} catch {
  toast.error("Upload failed. Try again.", { id })
}
```

## Styling

The wrapper maps Sonner to `--popover`, `--popover-foreground`, `--border` and `--radius`, so toasts follow light and dark themes. Do not pass colors per toast.

## Keyboard

| Key | Action |
| --- | --- |
| <kbd>Alt</kbd> + <kbd>T</kbd> | Moves focus to the toast area |
| <kbd>Tab</kbd> | Moves between action buttons on visible toasts |
| <kbd>Enter</kbd> or <kbd>Space</kbd> | Activates the focused action |
| <kbd>Esc</kbd> | Collapses the expanded toast stack while focus is inside it |

## Focus management

- Showing a toast never moves focus. People keep working where they are.
- Toasts pause their timer while hovered or focused, so there is time to reach the action.
- Any action in a toast must also be possible somewhere else, because toasts can close before people reach them.

## Checklist

- The toast area is a live region, so screen readers announce new messages without moving focus.
- Messages make sense on their own, without the icon or color.
- Default duration (4 seconds) is long enough for one short line. Raise `duration` for anything longer, or use an inline message.
- Undo is offered by a button in the toast and, where possible, another route like the item's menu.
- Errors that block progress are shown inline, not only in a toast.
