## When to use

- To name an icon-only button, so people know what it does before they click.
- To show a keyboard shortcut for a control.
- To reveal the full text of something that is cut off.

## When not to use

- **For information people need to finish a task.** Put it on the page as helper text.
- **For anything interactive, like links or buttons.** Tooltips disappear when the pointer leaves. Use a [popover](/components/popover).
- **On touch-only screens.** There is no hover. Make sure the control is clear without it.
- **To repeat a visible label.** If the button already says "Save", a tooltip saying "Save" adds noise.

## Toolbar

Tooltips work best in toolbars where icons sit close together. Hover across the buttons below: once one tooltip is open, the next opens right away.

## Content

- One short phrase, ideally under five words, in sentence case and with no full stop.
- For icon buttons, match the `aria-label` exactly.
- Add a shortcut after the label in quieter text, like "Bold Ctrl B".
- Never put the only copy of important information in a tooltip.

## Import

```tsx
import { Tooltip, TooltipContent, TooltipProvider, TooltipTrigger } from "@/components/ui/tooltip"
```

`TooltipProvider` is already mounted once around the whole app in `App.tsx`. You do not need to add it per tooltip.

`TooltipTrigger` accepts `asChild`. Always use it with a focusable element such as `Button`, so keyboard users can open the tooltip.

## Disabled triggers

Disabled buttons do not fire pointer or focus events, so the tooltip never shows. Wrap the button in a focusable `span`:

```tsx
<Tooltip>
  <TooltipTrigger asChild>
    <span tabIndex={0}>
      <Button disabled>Publish</Button>
    </span>
  </TooltipTrigger>
  <TooltipContent>Add a title before publishing</TooltipContent>
</Tooltip>
```

## Styling

Tooltips invert the theme: `bg-foreground` with `text-background`, so they stand out in both light and dark. Set a `max-w-*` class on `TooltipContent` if text might wrap.

## Keyboard

| Key | Action |
| --- | --- |
| <kbd>Tab</kbd> | Focusing the trigger opens the tooltip |
| <kbd>Esc</kbd> | Closes the tooltip without moving focus |
| <kbd>Enter</kbd> or <kbd>Space</kbd> | Activates the trigger as normal and closes the tooltip |

## Focus management

- Focus never moves into a tooltip. It stays on the trigger.
- The tooltip opens on keyboard focus as well as on hover, and closes when focus leaves.

## Checklist

- The tooltip text is linked to the trigger with `aria-describedby`, so screen readers announce it after the label.
- Icon-only triggers still have an `aria-label`. The tooltip is a visual aid, not the accessible name.
- Tooltip content is plain text. No links, buttons or inputs.
- Text and background use the inverted foreground and background roles and meet 4.5:1 contrast.
- The control makes sense on touch screens where tooltips do not appear.
