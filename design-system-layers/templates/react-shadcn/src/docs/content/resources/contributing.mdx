## Before you propose

Check whether an existing component or pattern already solves the problem. Most requests are a new use of something that exists.

## Proposal checklist

Open an issue with:

1. **The layer.** Foundation, component or pattern.
2. **The evidence.** Screens, research or support tickets showing the need.
3. **Why existing options fail.**

## Acceptance gates

| Stage | Gate | Question |
| --- | --- | --- |
| Propose | Useful | Is there evidence people need it? |
| Propose | Unique | Is it different from what exists? |
| Publish | Usable | Was it tested, including with assistive technology? |
| Publish | Consistent | Does it follow the foundations? |
| Publish | Versatile | Does it work in more than one place? |

Anything used in only one place stays local to that feature until a second team needs it.
